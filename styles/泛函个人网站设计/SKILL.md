# 泛函个人网站设计

## 工作顺序

1. 读取参考页面的 HTML、CSS、字体声明、断点和动效依赖。不要只看截图。
2. 记录可验证的字号、行高、字重、颜色、圆角、网格比例、留白和运动方式。
3. 把观察结果改写成自己的视觉语法。保留方法，避开原站商标、插画和独有品牌资产。
4. 为每种画幅重排信息。禁止把同一构图机械缩放。
5. 写真实、具体、能落到画面上的短文案。
6. 渲染检查，写入目标载体，再从目标端回读。

开始设计前读取 [design-language.md](references/design-language.md)。涉及飞书画板、矢量字形或文案检查时，再读取 [delivery-and-copy.md](references/delivery-and-copy.md)。

## 视觉判断

- 把颜色当成连续场景，不把页面切成一堆同尺寸卡片。
- 把展示字当成叙事画面。中文大标题默认使用阿里妈妈东方大楷；信息文字使用清晰的无衬线字体。
- 使用斜向语句带、圆形节点、错位和局部越界留下动作痕迹。
- 暖白负责阅读，深绿负责沉浸，近黑负责推进，淡紫负责回声与结果。
- 大字轻或有书写感，小字稳、短、便于扫读。
- 保持克制。每一屏只留下一个主要判断和少量可验证细节。

不得调用或套用 `beautiful-feishu-whiteboard` 的视觉风格、配色模板、组件样式或构图套路。需要飞书技术能力时，只读取 `lark-whiteboard`、`lark-doc` 等工具规范。

## 画幅规则

- 长海报：用完整色场轮换章节；每 800–1200 像素出现一次明显节奏变化；结尾换成回声色。
- 3:4：标题占上半场；语言轨迹穿过中段；事实落在稳定深色区域；封面远看也能读出一句话。
- 16:9：使用非对称双栏；左侧保留判断，右侧放工作台或证据；斜向元素承担视线连接。

## 飞书交付

- 优先使用可编辑的矩形、圆形、线段、文本和分组。
- 飞书文本节点无法可靠保存自定义字体族。展示字需要精确保留时，把大标题转成矢量路径；正文继续使用文本节点。
- 写入画板前运行几何检查；写入后导出线上预览，检查字体、裁切、层级和留白。
- 文档里写清颜色语义、字级、场景容器、网格、运动痕迹和三种画幅差异。
- 用户要求飞书文档交付时，完成后在客户端右侧打开该文档。

## 文案检查

先阅读 [delivery-and-copy.md](references/delivery-and-copy.md)，再运行：

```bash
node scripts/check-copy.mjs output.svg document.xml --keywords=语音,细节,方案
```

任何命中都要改稿。引用原文只有在用户明确要求时保留，并注明来源。

## 验收

- 参考代码中的结构规律能在成品里找到对应证据。
- 三种画幅有各自的构图，不存在等比缩放痕迹。
- 大标题的中文字形符合指定字体。
- 线上预览没有文字溢出、遮挡或节点错层。
- 文案扫描为零命中。
- 飞书文档和所有画板 token 回读正常。
